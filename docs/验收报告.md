## 一、基础设施

### ☑ 1. 后端可启动，前端可启动，前端能成功调用后端健康检查接口

```powershell
# 后端
java -jar science-platform-server/target/science-platform-server-1.0.0.jar
# 前端
cd science-platform-web && npm run dev
```

**实测**：`GET http://localhost:5173/api/v1/health`（走 Vite 代理）返回

```json
{"code":200,"message":"success","data":{"status":"UP","application":"science-platform-server",
"stage":"阶段 9：个人中心与站内消息","serverTime":"2026-10-30 19:29:13",
"db":{"status":"UP","database":"science_platform","publishedArticleCount":8}}}
```

首页会真实渲染这个结果（后端连接状态、数据库状态、已发布文章数），不是硬编码。

### ☑ 19. SQL 初始化脚本和 README 能让另一台干净环境按步骤运行项目

- `database/schema.sql`：可重复执行（先按依赖倒序 DROP 再建），20 张表、29 外键、72 索引
- `database/seed.sql`：可重复执行（先 DELETE 再插入），演示数据完整
- `README.md`：写明 JDK/Node/MySQL 版本要求、初始化步骤、配置方式、启动命令、演示账号
- 已知限制：`mysql.exe` 打不开含中文的路径，必须在 `database` 目录内用 `source schema.sql` 执行——此结论已写入 `database/README.md`

**实测**：多次从头执行 `schema.sql` + `seed.sql` 均成功，数据恢复为标准状态。

## 二、账号与权限

### ☑ 2. 普通用户可以注册/登录；密码不是明文保存

| 验证 | 结果 |
| --- | --- |
| 注册 | `POST /auth/register` → `200`，自动赋 `USER` 角色 |
| 登录 | `POST /auth/login` → `200` + JWT |
| 密码存储 | `sys_user.password_hash` 为 BCrypt（`$2b$10$...`），`SysUser.passwordHash` 标注 `@JsonIgnore` |

**实测**：注册 `test9388` 后用 `abc123` 登录成功；查库 `password_hash` 为 BCrypt 字符串。测试断言响应中不存在 `passwordHash` 字段。

### ☑ 17. 管理员与超级管理员权限区分明确；普通用户无法调用后台管理接口

| 角色 | 可访问 | 实测拦截 |
| --- | --- | --- |
| 普通用户 | 公开内容 + 个人功能 | `/admin/**`、`/creator/**`、`/review/**` 均 `403` |
| 创作者 | + `/creator/works` | `/admin/**`、`/review/**` → `403` |
| 评审员 | + `/review/**` | `/admin/**` → `403` |
| 管理员 | + `/admin/**` | `/admin/users/**` → `403`（仅超管） |
| 超级管理员 | 全部 | — |

**实现**：路径规则（`SecurityConfig`）+ 方法级 `@PreAuthorize` 双重限制；前端隐藏按钮只是体验，不构成安全边界。

### ☑ 16. 个人中心的作品、贡献、收藏、消息和投稿均按当前用户过滤

`/contributions/mine`、`/creator/works`、`/interactions/favorites/mine`、`/notifications`、`/events/submissions/mine` 全部以「当前登录用户 ID」为查询条件，**不接受前端传 userId**。

**实测（T12）**：`creator01` 标记 `user01` 的消息 → `404 消息不存在`；`creator01` 的消息列表不含 `user01` 的任何通知。

**实测**：`GET /articles?page=1&size=3` 返回 3 条 + `total=8`；`page=0` 与 `size=101` 均 `400`。

## 五、知识共建（项目核心）

### ☑ 7. 用户能提交知识补充/纠错建议，必须包含必要字段并保存来源信息

**实测（T06）**：缺字段时
`400 reason 提交理由不能为空；referenceSource 参考来源不能为空；suggestedContent 建议内容不能为空`，
且数据库无新增记录（测试比对前后条数）。

四个必填字段：`articleId`、`contributionType`、`suggestedContent`、`reason`、`referenceSource`。

### ☑ 8. 评审员能通过/驳回贡献并填写意见；提交者可查看处理结果

**实测（T07）**：
- 驳回不填意见 → `400 驳回时必须填写审核意见`
- 驳回填意见 → `REJECTED`，提交者在「我的贡献」看到状态与意见
- 评审员访问 → `200`；创作者访问审核接口 → `403`

### ☑ 9. 通过知识贡献后，正式文章内容更新，历史版本保存，相关通知生成

**实测（T08，端到端）**：对文章 8 提交纠错并通过后

| 项 | 变化 |
| --- | --- |
| 文章 `version_no` | 1 → 2 |
| 文章正文 | 523 字 → 596 字 |
| `article_version` | 新增 `version_no=1` 快照，内容为变更前的 523 字 |
| `source_contribution_id` | 指向该贡献，可追溯 |
| `sys_notification` | 新增 1 条 `REVIEW_RESULT` 给提交者 |
| `sys_operation_log` | 新增 `CONTRIBUTION_APPROVE` |

### ☑ 10. 审核被重复提交或重复处理时，系统不会产生错误的重复更新

两层防护：

1. 状态预检查：非 `PENDING` 直接 `400 该建议当前状态为已通过，不能重复处理`
2. 条件更新：`UPDATE ... WHERE id = ? AND status = 'PENDING'`，`affected == 0` 抛异常触发整体回滚

**实测**：重复通过 → `400`，且不产生第二条历史版本。

**T09 事务回滚**：用 `@MockitoBean` 让写快照抛异常后，
文章版本号与正文未变、贡献仍为 `PENDING`、`reviewerId`/`reviewedAt`/`finalContent` 全为 `null`、
通知与日志均无新增。

## 六、社区互动

### ☑ 11. 文章与作品支持点赞、评论、收藏；同一用户不会产生重复点赞/收藏

**实测（T10）**：同一用户连点 3 次点赞 → 三次均 `200`，`likeCount` 始终 1，数据库仅 1 条记录。
收藏同理（唯一索引 `uk_like` / `uk_favorite` 兜底）。

评论支持一层回复；删除权限：本人或管理员（他人 `403`）。

### ☑ 12. 用户可提交内容反馈，管理员可以查看并处理

**实测**：
- 提交 → `PENDING`，返回目标标题（针对评论的反馈显示「评论：<内容前 30 字>」）
- 后台列表 → 含提交人与目标
- 处理 → `RESOLVED`，写 `FEEDBACK_HANDLE` 操作日志
- 重复处理 → `400 该反馈已处理完毕，不能再次处理`
- 普通用户访问后台 → `403`

## 七、主题活动

### ☑ 13. 管理员可发布活动并设置时间和规则；活动状态展示正确

- 活动表存 `startAt`/`endAt` 与管理状态；**时间状态每次读取时现算**
- 实测：活动 1（10-01 ~ 12-31）→ `ONGOING`；活动 2（已手动结束）→ `ENDED`
- 时间状态：`NOT_STARTED` / `ONGOING` / `ENDED` / `UNPUBLISHED`

> 自查修正：初版只判断 `PUBLISHED`，导致已结束的活动被报成「未发布」，已修正。

### ☑ 14. 创作者可以在活动有效期内投稿；无权用户和超时投稿被拒绝

**实测（T11）**：

| 场景 | 结果 |
| --- | --- |
| 向已结束活动投稿 | `400 活动已结束，不能再投稿` |
| 向未开始活动投稿 | `400 活动尚未开始，暂不能投稿` |
| 提交他人作品 | `403 只能提交自己的作品` |
| 重复投稿同一作品 | `400 该作品已报名本活动，不能重复投稿` |
| 普通用户投稿 | `403` |

### ☑ 15. 评审员可对活动投稿评分和评论；活动结束后可以展示优秀作品

| 场景 | 结果 |
| --- | --- |
| 打分 1–5 + 评语（评语必填） | `200`，均分写入 |
| 同一评审员重复评分 | 覆盖而非新增（唯一索引兜底） |
| 评分越界 / 缺评语 | `400` |
| 管理员确认优秀作品 | `200`，出现在活动详情的 `awards`，带均分 |
| **给未评审的投稿标优秀** | `400 投稿 #4 还没有任何评审记录，不能直接标为优秀` |
| 评审员提交获奖名单 | `403`（仅管理员） |

> 「未评审不得标为优秀」对应开发档案 FR-EV-05，是本阶段的重点约束。

## 八、工程质量

### ☑ 18. 关键表单、异常、空列表、分页、未登录和无权限场景有基本处理

| 场景 | 处理方式 | 实测 |
| --- | --- | --- |
| 参数校验失败 | Bean Validation + 统一异常处理 | 中文拼接多条错误 |
| 未登录 | `RestAuthenticationEntryPoint` | `401` + 统一 JSON |
| 无权限 | `RestAccessDeniedHandler` | `403` + 统一 JSON |
| 资源不存在 | `BusinessException.notFound` | `404` |
| 路径不存在 | `NoResourceFoundException` 处理 | `404` 统一格式 |
| 方法不支持 | `HttpRequestMethodNotSupportedException` 处理 | `405` 统一格式 |
| 空列表 | 前端 `el-empty` | 知识库、作品、专题、活动、消息均有 |
| 分页 | 统一 `PageResult` | 列表页均可翻页 |
| 服务端异常 | 兜底处理，只返回通用提示，堆栈写日志 | 不泄漏 SQL/类名 |

## 九、验收结论

开发档案 12.1 的 20 条验收项**全部通过**。

### 已知限制（论文「不足与展望」素材）

| 类别 | 限制 | 影响 |
| --- | --- | --- |
| 检索 | 使用 `LIKE '%关键词%'`，无法命中前缀索引 | 数据量大时搜索较慢；未引入全文检索引擎 |
| 令牌 | 签发后无法主动撤销（无黑名单） | 改密码后旧令牌仍有效至过期（默认 2 小时） |
| 令牌 | 无刷新令牌机制 | 过期需重新登录 |
| 安全 | 无登录失败次数限制 | 理论上可暴力尝试 |
| 活动 | 到期后管理状态不自动变为 CLOSED | 只体现在 `timeStatus`，需管理员手动结束 |
| 投稿 | 不支持撤回 | 状态枚举已预留 `WITHDRAWN` |
| 前端 | Element Plus 全量引入 | 主包体积偏大 |
| 用户管理 | 按角色筛选在内存中进行 | 数据量大时结果不准 |
