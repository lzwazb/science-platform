# 项目结构核对（对照 A1–A7）

> **核对基准**：[项目结构基准.md](项目结构基准.md)（A2 关联已改为「可选」）
> **核对方式**：后端 28 个 Controller 的接口清单、entity/DTO 字段与业务校验、`SecurityConfig` 授权规则、前端 28 个页面
> **结论口径**：✅ 覆盖 ｜ ⚠️ 覆盖但有偏差/简化 ｜ ❌ 缺口 ｜ ➕ 基准外扩展
> 核对日期：2026-11-15

## 一、总览

| 模块 | 状态 | 一句话 |
| --- | --- | --- |
| A1 科普知识库与专题探索 | ✅ | 分类、列表、详情、搜索、专题齐全；搜索只覆盖标题+摘要 |
| A2 创作者中心与作品管理 | ✅ | 增删改查+审核流齐全；关联为学科级可选；无创作者专属资料 |
| A3 知识共建与纠错 | ✅ | 三类型、理由/来源必填、审核、版本快照齐全；通过意见已改为必填 |
| A4 社区互动 | ✅ | 点赞/评论/收藏/反馈对文章与作品都支持 |
| A5 主题创作活动 | ✅ | 发布→投稿→评审打分→优秀作品展示闭环 |
| A6 消息通知与个人中心 | ✅ | 资料、我的作品/贡献/收藏/投稿、四类站内消息齐全 |
| A7 后台管理与系统管理 | ✅ | 内容治理齐全，评论管理已补齐（2026-11-15） |

**没有 ❌ 缺口**，也没有跨模块「串位」；G1、G2 已修复，剩余 4 处为已记录的简化，见第四节。

## 二、逐条核对

### A1 科普知识库与专题探索

| 基准要点 | 证据 | 结论 |
| --- | --- | --- |
| 知识分类 | `GET /api/v1/categories`；`science_category`；`AdminCategoryController` 增删改 | ✅ |
| 文章列表 | `GET /api/v1/articles`（分页、categoryId、keyword）；`ArticleQueryService.pagePublished` | ✅ |
| 文章详情 | `GET /api/v1/articles/{id}`；`ArticleDetailView.vue` | ✅ |
| 关键词搜索 | `GET /api/v1/articles/search`；`LIKE` 于 `title`、`summary` | ⚠️ 不含正文 |
| 专题浏览 | `GET /api/v1/topics`、`/topics/{id}`；`topic_article.sort_order`；后台 `PUT /admin/topics/{id}/articles` 编排 | ✅ |

### A2 创作者中心与作品管理

| 基准要点 | 证据 | 结论 |
| --- | --- | --- |
| 创作者资料维护 | 仅 `PUT /api/v1/users/me`（昵称/头像/邮箱/简介） | ⚠️ 无创作者专属字段，复用通用资料 |
| 作品发布 | `POST /api/v1/creator/works`；`categoryId`（形态）必填校验 | ✅ |
| 作品分类 | `categoryId`（形态）+ `knowledgeCategoryId`（学科，选填） | ✅ |
| 作品编辑/删除 | `PUT /creator/works/{id}`、`DELETE /creator/works/{id}` | ✅ |
| 作品详情 | `GET /api/v1/works/{id}`；`WorkDetailView.vue` | ✅ |
| 可选择关联已有科普文章 | `knowledge_category_id` 选填；详情按学科实时查 `findArticlesByCategory` | ✅（按基准第四节口径） |

### A3 知识共建与纠错

| 基准要点 | 证据 | 结论 |
| --- | --- | --- |
| 补充/纠错/修改建议三类 | `ContributionSubmitRequest.contributionType`：`SUPPLEMENT|CORRECTION|MODIFICATION` | ✅ |
| 理由与参考来源必填 | `@NotBlank reason`、`@NotBlank referenceSource` | ✅ |
| 记录提交人/时间/状态/处理意见 | `knowledge_contribution`：`submitter_id`、`created_at`、`status`、`review_comment` | ✅ |
| 用户查看贡献记录 | `GET /contributions/mine`、`/{id}`、撤回 `/{id}/withdraw`；`MyContributionsView.vue` | ✅ |
| 采纳后更新正式文章并留版本 | `POST /review/contributions/{id}/approve` + `article_version`；`GET /articles/{id}/versions` | ✅ |
| 审核须有意见 | 通过、驳回都强制（`400 通过时必须填写审核意见` / `驳回时必须填写审核意见`） | ✅ 已对齐 FR-KC-03 |

### A4 社区互动

| 基准要点 | 证据 | 结论 |
| --- | --- | --- |
| 文章点赞/收藏 | `POST|DELETE /interactions/likes`、`/favorites`；`InteractionTargetResolver` 支持 `ARTICLE` | ✅ |
| 作品点赞/收藏 | 同一组接口，`targetType=WORK` | ✅ |
| 评论（文章与作品） | `GET|POST /comments`、`DELETE /comments/{id}`；回复通知被回复者 | ✅ |
| 内容反馈 | `POST /api/v1/feedback`、`GET /feedback/mine`、后台 `GET /admin/feedback` + `{id}/handle` | ✅ |
| 收藏混排与失效标记 | `FavoriteItemVO`（`targetType` + `available`）；`MyFavoritesView.vue` | ✅ |

### A5 主题创作活动

| 基准要点 | 证据 | 结论 |
| --- | --- | --- |
| 活动发布（说明/规则/起止） | `AdminEventController` 增改、`publish`、`close`；`creative_event.rules/start_at/end_at` | ✅ |

### A6 消息通知与个人中心

| 基准要点 | 证据 | 结论 |
| --- | --- | --- |

| 编号 | 偏差 | 优先级 | 建议处置 |

## 五、结论

七个模块**全部有落地实现**，接口与页面一一对得上，无模块缺失、无越界串位。
G1（评论后台）与 G2（通过意见必填）已于 2026-11-15 修复；G3–G6 记录进论文「不足与展望」即可。
