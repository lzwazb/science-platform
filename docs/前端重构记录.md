# 前端重构记录

> 依据 oil-ui 的流程执行：产品事实 → 方向 → 素材 → 实现 → 真实画面评审。
> 技术栈、接口契约、权限规则、路由名称一律不动，只重建**内容呈现层**。

## 一、方向

**让内容成为视觉主角。**

原来的封面是抽象几何 SVG（蓝底十字、绿底同心圆、紫底六边形），三张并排风格各异，
看着像临时占位图。对科普平台来说这是浪费——星系、染色体、病毒、晶体本身就很有视觉说服力，
却被抽象图形挡住了。

所以这一轮的核心动作：**用真实科学影像替换抽象插画，用学科色建立辨识度，用密度和排版拉出层级。**

## 四、页面改动

### 知识库（`KnowledgeListView.vue`）

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 网格 | 3 列 | **4 列**（1440 下每张 285px） |
| hero 高度 | 约 180px | 约 150px（padding 30/32 → 22/26，标题 26 → 21px） |
| 分类标签 | 统一蓝色 `el-tag` | 学科色竖线 + 学科色文字 |
| 卡片 | 1px 边框 + 阴影 | 极淡边框 + 悬停浮起 3px + 封面放大 1.045 |
| 标题 | 15px / 两行截断 | 13.5px + `text-wrap: balance` |

**为什么要 balance**：标题 19 字、每行约 17 字，自然折行会出现「…长期记 / 忆」这种孤字。
均衡两行长度后读起来顺，虽仍可能在词中断开，但比孤字好。

### 首页（`HomeView.vue`）

- hero 从 40/40/36 内边距压到 30/32/28，标题 32 → 30px，整体少约 70px
- 文章区固定 **3 列**（原来是 `auto-fill minmax(320px)`，1440 下会排 3 列但不稳定）
- 封面比例 16:7 → **16:9**，与全站统一
- 分类标签改学科色

**首页 3 列、知识库 4 列是刻意的**：首页是门户展示，卡片更大更铺张；
知识库是工具页面，追求一屏看到更多。两个页面因此有节奏差异。

### 文章详情（`ArticleDetailView.vue`）

- 顶部加 3px 学科色渐变指示线
- 分类标签从蓝色 `el-tag` 改为学科色竖线样式
- 阅读宽度继续用 `--sp-container-reading`（900px）

### 作品广场（`WorkListView.vue`）

- 网格 3 列 → **4 列**，断点与知识库一致

**作品封面保留原有的几何插画**。这不是偷懒：文章是「真实世界」，作品是「创作者再加工」，
两者用不同的视觉语言反而能区分开。而且现有 3 张作品封面本身风格统一（深色底 + 细线几何）。

## 五、实测中修掉的问题

**1. 标题孤字**

初版 14px、自然折行，出现「疫苗为什么有效：一次预演换来长期记 / 忆」，第二行只有一个「忆」。
改 `text-wrap: balance` + 字号降到 13.5px 后，8 条标题里 6 条能单行放下。

**2. 学科色标签不生效**

`--cat` 变量已经传到卡片元素上，但 `.article-card__category` 的颜色仍是品牌蓝。
原因是旧规则里 `color: var(--sp-primary-dark)` 写在后面覆盖了。重写整条规则后生效：

```
健康医学    → rgb(224, 100, 92)
地球与环境  → rgb(63, 158, 90)
信息技术    → rgb(139, 92, 246)
```

**3. 详情页指示线不显示**

我一开始选的是 `.article-card::before`，但详情页的容器 class 是 `.article-shell`。
改正后实测：`height: 3px`、渐变从 `rgb(21,160,129)` 起（生命科学青绿）。

**4. 卡片在浅底上「漂浮」**

去掉边框只用阴影后，卡片边界不清晰。补一条 `rgba(24,44,68,0.06)` 的边框压住。

## 六、实测中修掉的问题

**1. 「已结束」出现了两次**

活动列表与详情都同时用了「左上角状态角标」和「封面蒙层文字」，同一句话在一张卡上重复。
改为：ENDED 时只留蒙层文字，角标只在未结束的活动上显示。

**2. 底部浮条挡住卡片**

整页截图里浮条画在了页面中间，一开始以为是 `position: sticky` 算错。用真实视口滚动实测后确认：
那是 fullPage 截图对 sticky 元素的失真（截图时视口被撑高，sticky 重新定位）。

不过真实滚动下小屏的问题是真的：浮条一直贴在底部，压住下一张卡片的信息，而且在首屏和头部按钮重复。
改成**滚过 280px 才出现**（带 200ms 淡入），小屏压成单行 53px、只留「征集至某日截止」。
页面底部同时留 96px，滚到页尾时不会压住最后一张卡。

**3. 同一件作品在一屏里出现两次**

活动详情有「优秀作品」和「参赛作品」两个区，获奖作品会被两边同时渲染。
参赛作品区改为只列未获奖的投稿；全部投稿都获奖时给一句「本次活动的 N 件投稿均已获奖，见上方「优秀作品」」。
这样既保留完整名册，也不重复。

**4. 新公开接口被安全规则拦成 401**

`/events/{id}/submissions` 加好后游客访问 401。原因是安全配置里有一条通配
`GET /api/v1/events/*/submissions/**` → `authenticated()`，本意是保护「我的投稿」，
但它把整个 `submissions` 路径都算进去了。收窄为两个明确的 `mine` 路径，
实测：游客访问参赛作品列表 200，访问两个「我的投稿」仍 401。

顺手确认了一件旧事：`GET /events/submissions/mine`（跨活动）本来也不匹配那条通配，
一直靠 `/events/**` 的公开规则放行，只是控制器取不到用户而在业务层报错。现在一并归位。

# 技术债 5.1 收尾 + 第三批（2026-11-03）

## 一、三个旧页面迁移到 `ContentCard`

`ContentCard` 补了两个 props 之后，把首页、知识库、作品广场三处的自有卡片全部换掉：

| 页面 | 原本 | 迁移后 |
| --- | --- | --- |
| 知识库 | `.kb-card`（自有样式，105 行 CSS） | `ContentCard`，页面只留 `.kb-grid` 与分页 |
| 首页 | `.article-card` + `.work-card`（两套，共 160 行） | 各一个 `ContentCard`，页面只留网格与版本角标 |
| 作品广场 | `.work-card`（另一套，110 行） | `ContentCard`，页面只留网格与分页 |

新增的两个 props 是为了吸收三处的真实差异，而不是把差异抹平：

- `tag`：与学科并列的中性标签（作品形态「科普图文」这类非学科信息，不该用学科色）
- `metaRight`：元信息行右侧（知识库放日期、首页放「N 次阅读」）

合计删掉约 375 行重复 CSS，三处卡片的封面比例、圆角、hover 手感、标题折行从此只有一处定义。

**迁移中发现的问题**：`HomeView` 的 `.article-card` 其实还是**第一批重构之前的样式**——
封面 `16 / 7`、圆角 `12px`、标题 15px、网格是 `auto-fill minmax(320px)`。
第一批的记录里写的是「封面 16:7 → 16:9、文章区固定 3 列」，但那两处改动没有落到代码。
这次迁移顺带把它对齐到记录里承诺的规格（16:9、14px、3 列），并在记录里更正了这件事。

首页作品卡另有一处死代码：`关联 {{ work.articleCount }} 篇文章`——`articleCount` 恒为空，
删掉后改为显示作品形态与学科（与作品广场一致）。

| tab 数量 | 5 个（含空的「我的贡献」占位注释） | 4 个：我的作品 / 我的投稿 / 我的反馈 / 编辑资料 |
| 表格 | `el-table` 默认外观（粗边框、灰表头、底部多一条线） | 统一浅表头、无竖线、行高一致，`::deep` 一处定义 |
| 状态展示 | `el-tag` 默认色 | 语义色 pill：已发布绿、待审核琥珀、驳回红、草稿灰 |
| 空态 | 三个 tab 都是「还没有…」 | 各 tab 不同引导语 + 对应出处按钮（去创作者中心 / 看活动 / 去知识库） |
| 入口 | 我的贡献、我的收藏曾作为 tab | 顶部一行小链接，指向独立页 |

## 三、创作者中心（`CreatorWorksView.vue`）

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 列表 | 一张 `el-table` 混排所有状态 + 状态下拉筛选 | **按状态分组**：草稿 / 待审核 / 已发布 / 已驳回 / 已下架，各组带计数 |
| 顶部 | 标题 + 两个按钮 | 增加状态摘要条（共 N 件 + 各状态计数） |
| 行 | 表格行（ID / 作品 / 学科 / 状态 / 审核意见 / 浏览 / 操作） | 自定义行：封面 96×54 + 标题 + 学科色标签 + 简介 + 审核意见 + 更新时间 + 浏览数 + 操作 |
| 新建入口 | 只在右上角 | 没有作品时**移到页面中部的空态引导**（「新建第一件作品」）；已有作品时右上角保留 |
| 分页 | 服务端分页（size 10） | 一次取 100 件后客户端分组（分组与翻页冲突，见下文取舍） |

**取舍说明**：按状态分组和服务端分页是互斥的——翻到第 2 页时各组会缺条目。
作品数量本来就小，所以改成一次取回（接口上限 100）再分组，摘要条里显示真实总数。
真要做大数量下的分页，得改成「按状态分别查询」的接口，属于后续接口改动。

**实测中修掉的**：分组标题已经标了状态，每行再放一个状态 pill 就是第三次重复，换成「更新于 日期」更有信息量。

## 四、实测中修掉的问题

**1. 窄屏把标题挤成一字一行**

创作者中心的行动作列与右侧元信息列都是 `flex-shrink: 0`，375 下两列吃掉几乎全部宽度，
标题被压成「生命 / 密码 / 的乐 / 谱：」。改成窄屏分行：封面与标题一行、
「更新于 / 浏览数」一行、操作一行（带顶部分隔线）。标题另加 `flex-wrap`，学科标签自动换行不挤压。

**2. 个人中心指标区在窄屏出现「左边缘带分隔线」**

`flex-wrap` 下第 5 项换到第三行，仍继承偶数项的左侧分隔线，看起来像多了条竖线。
窄屏改用两列 `grid` + `nth-child(odd)` 去左线。
